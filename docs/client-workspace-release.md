# Client workspaces and discovery briefs

The agency dashboard prioritizes new inquiries, scheduled open-lead follow-ups,
client next actions, lead and client proposal statuses, blocked/near-term
milestones, and failed inquiry notifications. Counts reflect the full matching
set; each queue shows at most eight records. Calendar dates use America/Chicago.

Client workspaces contain contact and system details, access references (never
credentials), current scope, manually recorded proposal status/document links,
next actions, agreed support arrangements, linked original inquiries, private
notes, milestone reminders, and discovery briefs. Existing lead pipeline status
and history remain independent. Creating a workspace does not mark a lead won.

Discovery briefs can be incomplete drafts. Ready-for-review status requires goals,
deliverables, exclusions, client responsibilities, and acceptance criteria. This
status is an internal planning signal, not client approval or contract acceptance.
The saved brief can be printed/saved as PDF or downloaded as Markdown through an
authenticated, non-cacheable endpoint. Nothing is emailed automatically.

All new reads and writes enforce the existing administrator allowlist on the
server. Each new table has RLS and no browser-facing grants or policies.
Database access is server-side through the existing DATABASE_URL. Public website
pages, pricing, submissions, and analytics never import workspace data. Existing
admin authentication, lead features, pricing, notifications, imports, preflight,
audits, suppressions, and analytics remain. The previous overview is available at
/admin-portal/tools.

## Database and migration

Confirmed existing production target: Supabase **Orbisy**, project
`xjmoroanmpnipntmadcb`, database `postgres`, public application tables. The separate
`orbisy-development` project was inactive at inspection. No credentials are
recorded here.

Migration `drizzle/0009_client_workspaces.sql` was generated by the repository's
Drizzle tooling and adds five tables, their indexes/constraints, RLS, and explicit
revocations from PUBLIC, anon, and authenticated. It does not update or delete
existing leads, submissions, pricing, or other application records. New workspace
records are never seeded from inferred client identities or private inquiries.

Before applying, verify the intended DATABASE_URL with `npm run db:target`, check
migration history, and back up using the normal project procedures. Run
`npm run db:migrate` against that confirmed target. The Drizzle journal and snapshot
are included. If the migration is applied through the Supabase management tool,
record the exact migration SQL's SHA-256 and its journal timestamp in
`drizzle.__drizzle_migrations` in the same transaction, after checking that the
latest Drizzle migration is 0008. This keeps the two migration histories coherent.
Do not replay a raw migration over existing workspace tables.

The dashboard and lead page retain access to existing records while workspace
tables are missing; new workspace forms are withheld with an explicit setup
message. Connection failures are shown as unavailable rather than invented counts.

## Review checks

Use an isolated database to verify migrations, RLS/grants, existing-record
preservation, linked-lead integrity, transaction rollback, idempotent submissions,
optimistic edit conflicts, briefing readiness, milestone queues, complete counts
above the eight-row display limit, and authorization before all database access.

On a configured review deployment, sign in with the existing allowed admin account:

1. Open Overview and follow an inquiry or due action.
2. Create a workspace from an existing lead; verify its original inquiry remains.
3. Add another linked lead through the workspace search, then add a private note.
4. Save an incomplete discovery draft. Complete the required sections and mark it
   ready for review. Download and print the saved version.
5. Open the same workspace/brief in two tabs. Save one and verify the stale tab
   reports a conflict instead of overwriting it.
6. Add a blocked milestone and a next action due today; verify both dashboard links.
7. Archive and restore a workspace; verify records are retained and filters work.
8. Check logged-out redirects and a forbidden brief download, then verify the
   public website and existing private tools remain accessible as intended.

Proposal generation, e-signatures, payments, automated client emails, credential
storage, and detailed time tracking are not part of this first version.
